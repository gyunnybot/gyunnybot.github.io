## 직접 메모리 접근
초기 컴퓨터 시스템은 주변장치가 많지 않았고 CPU와 메모리의 속도도 빠르지 않았다. CPU는 입출력 명령을 만나면 입출력장치의 상태를 일정 주기로 반복 확인하며 데이터를 가져오는 방식(폴링, Polling)을 사용했는데, 물리적으로 훨씬 느린 입출력장치가 보내는 데이터를 전부 받을 때까지 그 작업만 붙잡고 있어야 했고 그동안 다른 작업을 수행할 수 없었다.

기술이 발전하면서 다양한 주변장치가 개발됨에 따라 장치별 제어를 전담하는 입출력 제어기(I/O Controller)가 도입되었다. 입출력 제어기는 CPU/메모리 쪽의 고속 버스와 주변장치 쪽의 저속 버스 두 채널을 중개하며 속도 차이를 완화했다. 그러나 이 단계에서도 입출력 제어기와 메모리 사이의 데이터 전송은 여전히 CPU가 관여했다.

이후 등장한 개념이 직접 메모리 접근(Direct Memory Access, DMA)이다. CPU는 DMA 제어기에게 \'어느 장치의 데이터를 메모리 어디로, 얼마나 전송하라\'는 명령만 내리고 이후 작업에서 손을 뗀다. DMA 제어기는 시스템 버스의 사용권을 CPU 대신 일시적으로 넘겨받아 입출력 제어기와 메모리 사이의 데이터 전송을 대행한 후 인터럽트로 CPU에 완료 신호만 전송했다. 덕분에 CPU는 입출력이 진행되는 동안에도 다른 연산을 계속 수행할 수 있게 되었다.

## 메모리 맵 입출력
메모리 맵 입출력(Memory-Mapped I/O, MMIO)은 CPU가 입출력장치에 접근하는 방식에 관한 개념이다. 입출력장치의 레지스터를 메모리와 동일한 주소 공간 일부에 매핑함으로써, CPU가 별도의 입출력장치 전용 명령어 없이 일반적인 메모리 접근 명령어(MOV, LOAD/STORE 등)만으로 장치를 제어할 수 있게 한다.

이는 CPU가 메모리 주소 공간과 입출력 주소 공간을 완전히 분리하고 전용 명령어(IN, OUT 등)를 사용하는 포트 맵 입출력(Port-Mapped I/O)과 대비되는 방식이다.

## MMIO로 인한 주소 공간 잠식 문제
CPU가 다룰 수 있는 전체 주소 공간의 크기는 주소 버스의 비트 폭에 의해 이미 고정되어 있다(예: 32비트 주소 버스 → 2^32, 약 4GB). MMIO는 이 정해진 주소 공간에 입출력장치의 레지스터 용량을 추가로 늘리는 방식이 아니라, 그중 일부를 입출력장치의 레지스터용으로 떼어 쓰는 방식이다. 따라서 MMIO에 할당되는 주소 영역이 커질수록 실제 RAM이 매핑될 수 있는 주소 영역은 그만큼 줄어든다.

대표적인 예시로 32비트 시스템에서 물리 메모리를 4GB 장착해도 그래픽카드 VRAM이나 각종 PCI 장치의 레지스터가 주소 공간의 일부(주로 상위 영역)를 MMIO용으로 차지하기 때문에 실제로는 3.5GB 정도만 CPU가 인식하는 문제가 발생하기도 한다. 이는 RAM 칩 자체가 부족해서가 아니라 RAM에 배정할 수 있는 주소가 부족해서 생기는 현상이다.

반면 포트 맵 입출력(PMIO)은 메모리 주소 공간과 완전히 분리된 별도의 입출력 주소 공간을 사용하므로 이러한 메모리 주소 공간 잠식 문제에서 자유롭다는 장점이 있다.

## 인터럽트
CPU가 작업을 실행하는 도중 입출력 완료 신호와 같은 이벤트가 발생(Event Driven)하면 CPU가 현재 진행 중인 작업을 일시적으로 중단하고 해당 요청을 우선 처리한 후 원래 작업으로 복귀하는데, 이를 인터럽트(Interrupt)라고 한다. 컴퓨터 과학에서 인터럽트는 꼭 입출력에 국한된 개념이 아니라, 기존의 CPU 작업 수행을 방해하는 의미로 광범위하게 쓰이는 용어이다.

## 인터럽트 처리 루틴
컴퓨터 시스템에서는 다양한 인터럽트가 존재하고, 또 동시에 여러 개의 인터럽트가 발생할 수 있기 때문에 배열 형태의 인터럽트 벡터(Interrupt Vector) 테이블을 사용해 여러 인터럽트를 하나로 묶어서 처리한다.

먼저 인터럽트 컨트롤러(Interrupt Controller)로 벡터 테이블에 저장된 인터럽트의 우선순위를 고려하여 CPU에 처리 순서를 통보한다. 이후 CPU가 각 인터럽트가 가진 인터럽트 번호에 대응되는 함수인 인터럽트 핸들러(Interrupt Handler)를 컨트롤러가 정해준 순서대로 실행하여 인터럽트를 처리한다.

## 인터럽트의 종류
인터럽트는 크게 내부 인터럽트, 외부 인터럽트, 시그널로 나눌 수 있다.

숫자를 0으로 나누거나 자신의 주소 공간을 벗어나는 작업을 하는 등의 CPU 작업 및 프로그래밍 오류와 관련된 인터럽트를 내부 인터럽트라고 한다. 실행 중인 작업을 이루는 명령어로 인해 발생하는 인터럽트로 \'동기적 인터럽트\', \'예외\'라고도 한다. 특히, 내부 인터럽트 중 시스템 콜에 의한 인터럽트를 \'소프트웨어 인터럽트\'라고 부른다.

\'비동기 인터럽트\', \'하드웨어 인터럽트\'라고도 불리는 외부 인터럽트는 주로 입출력장치로부터 오는 인터럽트나 전원 이상, 기계적인 오류 등에 의해 발생하는 인터럽트를 일컫는다. 앞서 언급한 DMA 제어기가 발생시키는 입출력 완료 신호도 외부 인터럽트의 한 종류다.

시그널은 \'Ctrl + C\' 명령어처럼 사용자가 임의로 발생시키는 인터럽트를 말한다. 실행 중인 포그라운드 프로세스(Foreground Process)를 중단하겠다는 사용자의 의도를 운영체제에 전달하는 용도로 사용된다.

## 인터럽트 번호
인터럽트가 발생하면 CPU는 해당 인터럽트의 번호를 이용해 미리 구성되어 있는 인터럽트 벡터 테이블에서 대응하는 핸들러의 주소를 조회한 뒤 순차적으로 처리한다. 이때 인터럽트 번호는 내부, 외부 인터럽트 순서대로 미리 할당되어 있다.

외부 인터럽트는 주로 입출력 인터럽트인 경우가 많은데, 이때 사용되는 IRQ(Interrupt Request) 번호는 인터럽트 번호가 아니라, 입출력 장치를 구분하기 위해 배정된 임의의 번호다. 실제로 IRQ 0번(타이머)은 인터럽트 번호 32번이며, IRQ 1번(키보드)이 인터럽트 번호 33번에 대응된다. 0번부터 31번까지의 인터럽트 번호는 외부가 아닌 내부 인터럽트가 우선적으로 배정받는다.

요컨대 IRQ가 인터럽트 번호와 일대일 대응되는 것은 사실이나, IRQ 번호와 인터럽트 번호는 다르다.
